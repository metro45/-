# OCR post-processing for Russian internal passports

Решение тестового задания: по результатам OCR паспорта РФ нужно либо принять
документ и выдать 10 полей, либо отклонить его. Принятый документ считается
верным, только если все 10 полей совпали с разметкой **и** паспорт действителен
на 01.10.2026. Ошибка при принятии дороже отказа, поэтому правило намеренно
консервативное.

## Быстрый старт

```bash
pip install -r requirements.txt        # numpy, pandas, scikit-learn
python postprocess.py data/test_predictions.jsonl answers.jsonl
```

Скрипт работает на CPU, без интернета и без обучения: все веса и словари уже
лежат в `models/` и читаются из JSON.

`answers.jsonl` содержит по одной строке на документ:

```json
{"doc_id": "te_00036", "decision": "accept", "fields": {"Last_name_ru": "...", "...": "..."}}
{"doc_id": "te_00001", "decision": "reject"}
```

Поля выводятся только для принятых документов (10 полей, формат как в
`train_labels.jsonl`).

## Структура репозитория

| Путь | Назначение |
|---|---|
| `postprocess.py` | точка входа: читает предсказания, пишет `answers.jsonl` |
| `pipeline.py` | контекст документа, извлечение кандидатов, признаки |
| `mrz.py` | разбор MRZ и проверка контрольных цифр (7-3-1) |
| `normalize.py` | нормализация строк, расстояния, токены, даты |
| `validity.py` | действительность паспорта на 01.10.2026 |
| `scoring.py` | логистические модели полей и документное правило |
| `train.py` | 5-fold OOF обучение, калибровка порога, сохранение моделей |
| `models/scorer.json` | веса 10 моделей + документное правило |
| `models/resources.json` | словари, token-map, reference-токены, code→org |
| `models/oof.jsonl` | OOF-предсказания для анализа ошибок |
| `data/`, `reference/` | исходные данные и справочник |
| `REPORT.md` | отчёт: EDA, метод, метрики, прогноз на test |

## Как устроено

1. **MRZ.** Разбираются обе строки, проверяются контрольные цифры номера,
   даты рождения и композитной части. Если проверки проходят, MRZ считается
   надёжнее визуальной зоны; если визуальная зона и MRZ совпадают, значение
   берётся из визуальной зоны (там корректная кириллица).
2. **Имена.** Сравниваются визуальная зона и MRZ с учётом дефисов/пробелов;
   расхождения в один символ исправляются по уверенности символов, остальные
   случаи отклоняются.
3. **Свободный текст** (место рождения, орган выдачи). Применяются
   token-map, выученный на train (частота ≥ 3, точность ≥ 0.95), разбиение
   слитных сокращений, осторожная правка неизвестных токенов по словарю
   (edit distance 1–2, высокая частота), сверка со справочником подразделений,
   восстановление точек после сокращений и lookup `код → организация`.
   Для `Birth_place_ru` действует toponym-gate: все слова должны быть в словаре
   золотых токенов или в справочнике подразделений, хотя бы одно — конкретное
   название, а значение не должно начинаться с административного хвоста
   (`Р-НА`, `ОБЛ.`): так отсекаются обрезанные строки. Название населённого
   пункта защищено от правки по справочнику. Для фамилий действует
   surname-gate: неизвестная фамилия на `-ШЕНСКИХ` отклоняется, потому что
   Ш/Щ в viz и MRZ совпадают и надёжно не различаются.
4. **Скоринг.** Для каждого поля — логистическая регрессия по признакам:
   результаты MRZ-проверок, уверенность символов, доля известных/неизвестных
   токенов, совпадения со справочником, правдоподобие имени по биграммам,
   точное совпадение со значением из train, дубликаты в батче, source/quality.
5. **Решение.** Документ принимается, если все 10 полей заполнены, каждое поле
   выше своего floor, произведение десяти вероятностей ≥ `0.98`, пройдены
   toponym- и surname-gate, а паспорт действителен на 01.10.2026.

## Обучение

```bash
python train.py
```

Скрипт делает 5-fold OOF (fold = `crc32(doc_id) % 5`). Все словари, token-map,
`code → org` и статистики имён пересобираются внутри каждого фолда, поэтому
OOF-оценка не содержит утечки разметки. Итоговые модели обучаются на OOF-строках
признаков, а не на признаках, посчитанных с полной разметкой: иначе собственные
метки документов попадают в словари и модель перестаёт переноситься на test.

## Ограничения

Правило консервативное: на OOF принято 227 из 3000 документов (7.6%), из них
0 с ошибкой (95% верхняя граница 1.66%); nested-процедура даёт 364/1 (0.27%).
На test принято 166 документов (8.3%), прогноз — 0–1 ошибка, верхняя граница не
более 3. Порог 0.98 выбран с запасом от первой ошибки (0.9484) и компенсирует
то, что на test словарь toponym-gate шире, чем в OOF. Toponym-gate строг к
редким топонимам; surname-gate детерминированно отсекает неразрешимую
Ш/Щ-неоднозначность. Правило узкое намеренно: 163 из 166 принятых на test
фамилий отсутствуют в train, поэтому общий фильтр неизвестных фамилий отбросил
бы почти всё. Остаточный риск — шум разметки, редкие имена/топонимы и другие
пары вроде О/Ё. Если важнее покрытие, 0.95 даёт 352/0 на OOF и 231 на test;
0.92 — 400/1 и 275. См. `REPORT.md`.
